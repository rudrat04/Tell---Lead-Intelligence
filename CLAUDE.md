# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Tell is a self-hosted lead-signal engine: it finds companies (and people) who need what the operator sells *right now*, explains why with cited evidence, ranks them, and emails a daily digest. The code is business-neutral; everything about a business (ICP, signals, role patterns, prompts, sources, recipients) lives in a **config pack**. The design source of truth is plan v3 (`gtm-signal-engine-plan-v3.md`, kept outside the repo); `PLAN-next.md` (git-ignored) tracks deviations, gaps and eval requirements.

**The repo is public** (free GitHub Actions minutes). Never commit packs other than `packs/example-gtm`, `.env`, `digest-preview.html`, or anything naming real leads. Scripts that run in CI must print **counts only**: Actions logs are public. `--show`, `--dry` and `--test` flags that print or render lead details refuse to run when `CI` is set.

## Architecture

Packages (`packages/*`, imported as `@tell/<name>`, `main` points at `src/index.ts`):

- **config**: pack schema (zod) + loader (local dir or R2 via aws4fetch) + `loadFixturePack()` for tests. The ICP (`icp.yaml`: which companies) and the target buyers (`buyers.yaml`: which people, with department, seniority, years, `decision_power`) are separate files; the loader stores buyers as `icp.personas` (packs without buyers.yaml keep personas in icp.yaml). Optional files fall back to defaults (`tools`, `critic`, `gigs`, `copy`). `CODE_SIGNAL_TYPES` lists signal types the code emits; a pack must define every one.
- **db**: Drizzle schema, migrations, `getDb()` (neon-http), `migrateDb()`. Re-exports `eq/and/inArray/sql` — import them from `@tell/db`, not `drizzle-orm`, or you get duplicate-type errors from two drizzle instances.
- **watchers**: source adapters (HN/Algolia, Reddit, web search via Serper (titles + snippets only, never fetches LinkedIn/X), YC directory + jobs pages, Greenhouse/Lever/Ashby, Keka/Freshteam, Common Crawl index, Remote OK, Himalayas, Workable), robots.txt, politeness (`politeGet`, per-host gap), bot identity, and `policy.ts` (per-source terms-of-use gates).
- **extract**: the LLM gates. Gate 3 post extractor and Gate 4 verifier (Claude Haiku 5.5, prompts built from the pack), `runCascade`, `HaikuClient` (classification, thinking disabled; cost tracking) and `WriterClient` (the analyst's opener, email and LinkedIn drafts: Claude Sonnet 5.5, adaptive thinking at `ANALYST_EFFORT` low (default) or medium, server-side refusal fallback, its own daily cap `WRITER_DAILY_CAP_USD` in `usage_daily` as `sonnet`).
- **intel**: pure logic, no I/O: Gate 1 rules, Gate 5 corroboration, ICP hard filters, job classification + daily board diff, scoring/ranking, gig rules.
- **people**: entity resolution (domains via tldts with private suffixes, never-guess rules, HN profile mapping), signal/person-lead persistence, contact picking by persona.
- **pipeline**: orchestration that touches the DB: tick, board discovery/check, scoring run, contacts enrichment, gigs.
- **deliver**: digest rendering + Gmail API sender + `runDigest`, Google Sheet (append rows, read labels back).
- **ops**: backups to R2, janitor (plan section 12 retention), usage guard, `computeMetrics` (nightly production evals into `eval_results`, shown in the digest health line), `forgetPerson`.

`evals/` holds the golden sets (`evals/golden/*.jsonl`, synthetic data only) run by `evals/golden.test.ts` in CI: role families, gig rules, Gate 1, staffing agencies, ranking archetypes (pairs that must rank in order). Each row's `note` names the false-positive class it guards; add a row whenever a new class is found.

Data flow:

```
tick (30 min):   watchers (HN, web search ≤ per_day) → seen-hash skip → Gate1 → Gate3 → Gate4 → resolve → signals | person_leads
daily chain:     migrate → pack:check → partitions → funding → jsearch → discover (daily slice) → boards:check (diff jobs) → gigs → tick (fallback) → digest
digest:          runScoring (signals → evidence → plays → score → rank) → company facts → need check (role gaps) → re-score
                 → contactsFor → buyer part of the score (re-rank) → analyst drafts (angle from the play) → render → send → deliveries
daily slice:     boards:discover --daily (rotating Workable query x location searches + Common Crawl tenants already listed): the set of companies keeps growing
weekly:          boards:discover (YC → ICP hard filters → accounts + job_boards; own-site ATS links)
                 + Common Crawl → Keka/Freshteam tenants → backlink proof → accounts + job_boards (India coverage)
                 + Workable search (pack `sources.workable`) → company site from Workable → board subdomain proven by account uid → accounts + job_boards
```

Key invariants (each was a real bug or a deliberate design decision):

- **Job openings are state, not events.** Scoring reads the `jobs` table: an open *core* role is current (age 0); adjacent/founding roles age from posting but never past 45 days while open. A closed role keeps its open-age plus the days since closing (closing never makes it look fresher). Job-derived rows in `signals` are ignored by scoring (`JOB_STATE_TYPES`) so a role never counts twice. Posting dates before 2000 or in the future are no date (`postedDate()`; Keka sends `0001-01-01`).
- **Watch findings are states too** (`STATE_SIGNAL_TYPES`: tool overlap, stack sprawl, leaky capture, agency credit): the weekly watch upserts them, keeping `observed_at` (first seen) and moving `signals.last_seen_at`; seen within 15 days = current with age capped at 30, otherwise they age from last seen. Change events (new tool, CTA change) stay one-off.
- **The score is a sum of readable parts** (Nov 2026; pack `signals.score`, default need 50 + fit 20 + timing 15 + buyer 15 = 100): need = log lift of intent over `base_rate`, full at `full_need_lift` (each signal decayed once, by its own `half_life_days`, inside intent); fit = `softFit`; timing = 0.5^(days/14) of the newest *event* (still-true states only count when there's nothing else, or every account looked brand new); buyer = `decision_power` x reach factors, half until contacts are known (`withBuyer` in the reach step). `priority` = score / 100; `displayScore()` = the 0-100; every lead shows "Score 58 = need 18 · fit 15 · timing 12 · buyer 13". The old product `intent x fit` with a saturating display (1 - base/priority) bunched every lead at 74-82; `soft_fit.influence` is now ignored.
- **Role families are generic**: `core` = the role the operator substitutes for (long-open → "struggling to hire", removed fast → filled); `adjacent` = the need is forming. Patterns live in the pack's `roles.yaml`.
- **JSearch roles** (`pipeline/discover-jsearch.ts`): employer domain = JSearch's website or the apply link's own site, never a job site/ATS host, and must match the employer name. A company whose site links a readable ATS board gets that board instead; otherwise roles sit on a `jsearch` board (skipped by `boards:check`), refreshed when seen again and closed after `close_after_days` unseen. Monthly quota summed from `usage_daily` (`jsearch`), counted before each request, never retried.
- **Region scope**: with `icp.hard_filters.regions_any` set, the daily board check, the weekly watch and the infra watch skip accounts scoring can never use (`regionInScope` / `regionInScopeSql`: known region on the list; unknown is out, as in scoring), and the digest's board health counts only those boards. Fetching 1,060 YC pages daily for out-of-region accounts got the crawler throttled after ~270, so YC is capped per run: the daily board check takes the least recently checked `MAX_YC_BOARDS` (300) YC boards (ATS APIs are all checked daily) and the weekly watch a rotating `MAX_YC_PAGES` (1,200, a safety cap) slice. Region comes from job locations for every non-YC source (`regionFromPostings`: the country holding at least half the located roles, India winning a tie; names match YC's, e.g. "United States of America"), and discovery keeps only regions in `regions_any`.
- **Board diff**: a board's first check is a baseline (no "new role" signals); a role is only announced as new if posted within 14 days; an empty fetch with ≥3 open roles is "suspect" and closes nothing.
- **Seen-hash dedupe** marks only items that actually went through the cascade; `lastRunAt` advances only on a clean, complete run (catch-up after outages).
- **Never guess a domain.** With a company name, exactly one candidate domain must match it; tool/vendor/ATS/free-mail domains are excluded (`domains.yaml`); homepages must load on the same brand. Reddit authors map from the post only (Reddit Responsible Builder Policy). An ATS tenant (acme.keka.com) becomes an account only when a candidate site's own pages link back to that exact board (Workable: the account API's `uid` must equal the search result's company id); slugs and names only suggest which sites to check. Region comes from job locations, never from the ATS. Staffing-agency boards are skipped: by name, by "for our client" texts, or by a title naming the client ("- Hiring for Northwind Hospital"); the daily board check marks existing ones `status: staffing` and closes their roles. DNS records prove mail hosting, not a CRM (Zoho Mail SPF is not Zoho CRM: pack `tools.yaml`).
- **Scoring by need and reach**: plays can `qualify` on their own (`min_count`) and name problem-owner buyers (`personas`, contacted first, any size); the digest scores a pool of `pool_multiplier` x the leads, finds contacts and emails, fills in the buyer part (decision power x `icp.reach` factors) and re-ranks.
- **Need check** (`pipeline/role-gap.ts`, pack `roles.gaps`, ported from job-post-notifier's founders list): for pool accounts and accounts where an empty seat would complete a play (`gapCandidates`), one Exa people search for current holders of the role groups the operator fills (e.g. GTM, Founder's Office, Product Marketing). Nobody in a group = `role_gap` state signal ("Missing: GTM · has Founder's Office: ..."), shown in red on the lead; holders are saved as people (a core-role holder becomes `ops_owner_known`). Re-checked every 14 days, `ROLE_GAP_PER_RUN` (20). Written on dry runs too (facts, not deliveries). People search misses people, so `role_gap` is weak alone (found at 19 of 20 accounts): it mostly completes plays.
- **Ranking with an optional floor**: probabilities are uncalibrated, so leads are ranked; `delivery.digest.min_score` (display score 0-100, 0 = off) keeps anything below it out of the email and Sheet, fast lane included, checked before contacts and again after reach re-ranking. `delivery.digest.region_groups` splits the digest into separate top-N lists by region (each ranked alone, own heading, optional own `min_score`, `regions: []` = the catch-all; `minScoreFor`, `rankByRegionGroups`); `max_leads: 0` = no cap. Fast lane = fresh (≤14d) strong signal, guaranteed a slot, not the top.
- **Idempotency** is enforced by unique keys (signals on `evidence_url,type`; plays per account; people per account+name+source; gigs per source+external id; digest once per IST day via `runs.idempotency_key`).
- **Spend**: Haiku daily cap (tick classification) and the Sonnet writer cap (digest drafts) are persisted per IST day in `usage_daily` (`haiku`, `sonnet`); every run checks remaining budget. Spend caps reaching their limit are a quiet "cap reached" note in the digest health line; only the usage guard's free-tier services (`FREE_TIER_SERVICES`) warn.
- `raw_items`, `candidates`, `scores` are monthly-partitioned (migration 0001); `ensure-partitions.ts` runs daily.
- **Company facts from Exa** (`pipeline/company-facts.ts`): pool accounts with no size, segment or description (`accounts.description`, Nov 21 2026: what they do, cut to a sentence or two by `profileLine`; passed to the judge, drafts and follow-ups as "What they do", and the Sheet's "What they do" column) (Keka / Workable / JSearch) get one Exa company search, accepted only when the result's website is the account's own domain; headcount becomes a size band (under the minimum or over the last band gets a band the pack lacks, so the ICP check drops it), and Haiku picks a segment from pack `icp.segment_descriptions`. Checked once per 90 days (`people_searches`, persona `company:facts`), `EXA_COMPANY_PER_RUN` (20); the digest re-scores after it. `formatLeadsTab` sets dropdowns, widths and the hidden ID by header name.
- **Sheet rows by column name**: `LEAD_COLUMNS` is the vetting order (Score, ICP fit, Timing, company, why, person, Email / Verified / Risky / Catch-all, your columns, drafts, hidden ID). Stored rows (`deliveries.sheet_row`) are objects by column name (old positional arrays convert via `storedRow`); appends and fills find columns by header, so columns can be moved in the Sheet. Email holds the address only.
- **One-tap labels**: real digests carry signed 👍/👎 links (`TELL_LABEL_URL` + `LABEL_SECRET`) to the Worker, which shows a confirm page (GETs never label: link scanners prefetch) and stores taps in KV; `sheet:sync` pulls them, fills empty Label cells, then acks. The Sheet stays the single source labels are read from.
- **`digest --test` records nothing**, so repeated test sends show the same leads; only real (scheduled) digests write `deliveries`.
- **Re-delivery** (`redelivery()` in `intel/rank.ts`): a delivered account is held for `redeliver_after_days` (90) and comes back early on a new play or new strong evidence (first seen after the delivery: strength ≥ `alone_min_strength` or a new type; a role posted before the delivery but found later isn't new), with a "Back on your list" reason in digest + Sheet. 👎 holds it past the window (only a new play brings it back); outcome meeting/won never comes back. Labels come from the Sheet via `sheet:sync`.
- **Their customers are the proof** (Nov 21 2026, `pipeline/buyer-signals.ts`, `extract/buyers.ts`): every draft for every industry reads why-now (the lead's own trigger) → two or three of THEIR customers showing new demand (accounts in the industries that buy from them, with a fresh demand signal, `SAMPLE_DAYS` 60, the lead's region first) → what you do in one plain line → the question. Who buys from a lead is worked out once from its description (Haiku, `buyerProfile`: only pack industries and demand signal types, job/site states excluded) and stored in `accounts.buyers` (re-worked after 120 days); no description or fewer than two matching companies = no sample (a play's public-record list sample, when it has one, comes first). The closing line comes from `copy.pitch` (`by_play`, else a `variants` entry picked by play and domain; judged plays map to the pack play for their signal), always reworded (the copied-run check covers it). `copy.plain_words.banned` are rejected in drafts for every industry not in `allow_segments` (niche readers get everyday words).
- **Opening emails and LinkedIn first messages follow the pack's `copy.yaml`** (voice, mention rules, offer ideas per play, closing styles, `never_say`, examples, `greeting`, `linkedin` voice/max_words/examples). The prompt encodes what reply data agrees on, not a copywriting formula: short (`delivery.email.max_words`), simple words, one relevant observation, a point of view, and an interest question instead of a time ask. Code rejects drafts that count durations, use a banned phrase, copy 9+ words of the brief (`COPIED_RUN`), start mid-thought, ask for a call/meeting/minutes, introduce the sender or say "I help companies", or don't end on a question; the LinkedIn message also can't pitch or link. A failing draft is rewritten with the reasons (`MAX_REWRITES` 2), keeping the good half from earlier tries; still failing = empty cell, never a template. Greetings are written by code from `copy.greeting` / `copy.linkedin.greeting`. The system prompt (brief included) is in the analysis cache key, so editing `copy.yaml` re-writes drafts; `pnpm drafts:backfill` re-writes the Opener / Email draft / LinkedIn message cells of rows already delivered (code-owned columns, overwritten).
- **ICP re-checked at scoring** (critic `icp`): discovery runs the hard filters once, so scoring drops accounts whose stored facts no longer fit the pack (excluded domain, a size band or segment the pack no longer has, a YC company whose latest seed fails). **Unknown-size enterprises** (Keka/Workable/JSearch accounts have no size): critic `enterprise` drops one whose job/evidence URL is on an enterprise careers system (pack `critic.enterprise.url_patterns`: Workday, SuccessFactors, branded locale portals), and the reach step drops one whose contact has a regional / business-unit title (`title_patterns`). Size is otherwise neutral (0.5 fit).
- **"Good time to message" is a label, never a score** (`intel/send-window.ts`): Message now / Good time / Can wait from the lead's own signals (fresh ask or contract role, stalled core role, leader in their first 90 days, recent raise or launch, role just filled against) plus the buyer's calendar (pack `icp.calendar`: financial-year start, quarter starts, budget planning months, quarter-close days, quiet periods). Shown on each digest lead and in the Sheet's appended "Timing" column. Leader titles for `new_gtm_leader` come from pack `roles.leaders` (empty = built-in GTM titles).
- **Industries** (`industries.yaml`, Nov 21 2026): one entry per industry (label, aliases, description, regions, team_size, fit, buyers, offer, opportunity, list); the loader expands it into segment_map / segment_descriptions / industries_any / segment_overrides / soft_fit.segment (`expandIndustries`; a segment also defined in icp.yaml is an error). The play builder gets the account's industry (opportunity, offer, buyers); a play without its own `offer` uses its industry's in drafts (except `list: gtm`). Plays and industries name the `list` generator their offer promises, so an email never offers a list public data can't build. Drafts reject overclaims in code (`OVERCLAIM`: none of them / the only supplier / guaranteed / exclusive).
- **Industry scope** (Nov 21 2026, `config/wiring.ts`): one industry gets the signals that are necessary and enough to make it an offer, and nothing from another industry leaks in. `industries.<seg>.signals` = the types that count for its companies (others are dropped in `scoreAccount` via `industryEvidence` before eligibility, plays, the judge and drafts; negatives always count; unset = all); `plays.<id>.industries` = the industries a play fires in (empty = any, unknown industry included; a scoped play never fires on an unknown industry); `capabilities[].industries` = who a capability may be offered to (`capabilitiesFor`; the judge is told the allowed ids and code rejects others). In judged mode an industry with no free capability on offer (or an unknown industry once capabilities are scoped) is never a lead. The schema errors on unknown industries/types and on a scoped play that needs a type its industry doesn't count; `packWarnings` (pack:check) / `pnpm pack:map` flag the soft gaps: a niche source writing a type its industry ignores (wasted lookups), counted types no source writes (declare the ones you bring in yourself in `sources.niche.imports`), unscoped plays or list capabilities open to every industry, plays naming buyers the industry doesn't list, an industry in no digest list. Paths that read signals outside scoring check `industryCounts` too: same-day alerts (an off-industry signal is never an alert, and the play must be scoped to the account's industry), follow-up "new facts", the need/owner check (no GTM-seat people search for industries that count neither `role_gap` nor `ops_owner_known`), and the site / DNS / infra watch (`industryCountsSql` with `WATCH_SIGNAL_TYPES`: no page fetches for industries that count none of what it writes). `GENERAL_SIGNAL_TYPES` = what general sources write; every other type must come from a niche feed (`nicheFeeds`) or `pnpm niche import`. Golden set `industry-scope.jsonl`.
- **Judged scoring** (`signals.score.mode: judged`, opt-in, Nov 21 2026; default `legacy` is unchanged): `pipeline/judge.ts` + `extract/judge.ts`, one Haiku call per gate-passing account (`judgeCandidates`, wider than the pool, round-robin across digest lists, `score.judge.per_run`, stops after 3 failures in a row) rates specific / urgent / prize / deliverable (anchored 0-5; code cuts uncited scores above 2 to 2, prize needs an amount in the cited quotes, deliverable 4+ needs a free capability whose `list` has its inputs in the evidence via `listReady`) and writes the play with an offer from `capabilities.yaml` (one free step + paid ones; unknown ids = not a lead). Parts: need = (specific + prize + deliverable)/15, timing = urgent/5, fit = reply rate learned from labels (`learnedFor`: per industry and play bucket, `min_bucket`, shrunk by `shrink`, 0.5 = average), buyer as before; the digest line shows the ratings. Stored in `built_plays` keyed by evidence + `playVersion` (prompt + catalog + industries hash). Once the judge works in a run, `requireJudged` keeps unjudged accounts out of the lists (no mixing of scales); if it can't run (no credit, outage) legacy scores stand. Exploration (`explore_share`, only once there are labels to compare) swaps under-tested industries into each list (`applyExploration`), recorded as delivery kind `exploration`. The library: judged plays with 2+ positive outcomes become the judge's examples per industry.
- **Copy that sells the system** (Nov 21 2026): every email = an insight from the lead's own record first (no forced "saw/noticed"; `opening_patterns` empty), proof = a small real sample (`proofSample`: the true total + 2-3 rows from the list the play's free capability names, added to the analyst's evidence so its numbers pass the checks; the full list stays with the operator), the system in one line, then a question that opens a sales conversation (never "want the names?" / "reply send": `never_say`). `copy.voices` / `copy.ctas_by_segment` pick voice and closes by the lead's industry, `copy.shapes` rotate the email structure by domain. `replyCheck` (Haiku) scores a draft that passed the fact checks 1-5 on whether a busy person would reply; under `REPLY_CHECK_MIN` it is rewritten with the critic's fix (within `MAX_REWRITES`). The need check is now an owner check (pack without `role_gap`): only accounts with sales-hiring signals, only GTM-owner titles; a holder counts against the lead, absence says nothing. Judged "prize" also stands on a cited size (`SCALE`: 4 sales roles, 120 people, 25 trucks); two cited hiring signals count up to 2.
- **Plays built from evidence** (`plays.build`, Nov 21 2026): when no pack play matches, the digest asks Haiku (`extract/play-builder.ts`) to build one from the account's top evidence: need, angle, offer, buyers, citations.
